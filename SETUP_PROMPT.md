# Setup prompt for a coding/deployment agent

You are setting up the supplied JEV Sentinel reference package on this machine.
Use the package's real source, README, SECURITY.md, docs/ADAPTERS.md and
primary-source references. Do not invent a native hook contract or claim that a
file copied into a directory is already active protection.

Inspect the package, Python 3.10+ availability, actual harness binaries, their
versions, and configuration roots. Do not print credentials or read full agent
transcripts. Run `python install.py` to preview detected harnesses. The intended
target family is OpenClaw, Hermes, OpenCode, Codex, Claude Code, Pi, Gemini CLI,
Cursor and Copilot CLI. Use explicit repeatable --profile arguments for alternate
accounts, and do not assume an installation on one host protects another container
or cloud agent. Do not use sudo to broaden access.

The user has asked for installation code; that alone does not authorize you to
change their machine. If this prompt is accompanied by an instruction to actually
install, apply only to the selected detected/explicit profiles with --apply. Begin
in shadow mode. Preserve native permission policies, other hooks, configuration
comments, secrets, model choices, /compact and /prune. Do not use dangerous trust
bypass flags. If a strict-JSON check, symlink/junction guard, schema validation,
or conflicting edit prevents an installation, preserve the file and report the
specific unsupported condition. Do not force an unsafe rewrite.

Run the Python tests and the optional Node adapter tests. Treat them as software
contract tests, not an effectiveness benchmark. Verify the actual plugin/hook is
loaded in each real harness after the required reload/restart. Codex requires
native /hooks review of exact command definitions. Hermes may require native enable
if its CLI was absent when staging. Do not fabricate completion of human trust
prompts. Run only harmless, disposable plumbing canaries from docs/OPERATIONS.md.
Never use destructive commands or real secrets in a canary.

Do not make live TypeSafe requests, incur API costs, or submit repository/private
content unless the user explicitly authorizes remote processing. Remote activation
requires backend=jev, TYPESAFE_API_KEY available to the actual harness process,
and JEV_SENTINEL_ALLOW_REMOTE=1. Never write API keys into tracked files or echo
them to logs. Keep the default pinned model unless the user deliberately changes
it and evaluates the new model. A failure or missing answer must not become an
allow. Enforce mode should be enabled only after the user requests enforcement
and the loaded runtime is checked against representative benign and adversarial
workloads; the included thresholds are not validated production values.

Review routing must preserve authority boundaries. Use the local metadata outbox,
an explicitly selected HTTPS admin endpoint, or a read-only review callback.
Do not launch a reviewer with more privileges, automatically approve blocked
operations, or treat a model's explanation as permission. Post-tool observers
cannot undo a tool that has already run. Unknown-goal adapters cannot claim full
user-intent alignment. Preserve the host's ordinary sandbox and approval checks.

Report each profile separately: detected versus staged, exact files changed,
backups, required native activation, native runtime canary outcomes, shadow versus
enforce mode, local versus Jev backend, known uncovered tool paths, and any tests
not performed. Include precise uninstall instructions using the same state-dir.
Do not claim complete prevention, all-harness cloud coverage, live model accuracy,
or same-UID tamper resistance. For stronger isolation, propose a separate-identity
broker/read-only control plane as an additional deployment task rather than
pretending the local installer creates it.
